# Owner rulings, phase 3 (issue 26), 2026-11-15

1. PR rule (P3R2-1, criterion 3): every done row's Status cell must hold either `PR #N` or an explicit `no PR`. A done row with neither is refused (exit 10). Nothing in prose is ever read: no whole-file fallback. Existing checkpoints and the template add `no PR` to rows that have none.
2. CI due (P3R2-3, P3R2-7): when a PR shows no CI runs, whether runs were due is decided at the PR record's head commit (`.github/workflows` at head_sha), not the workdir's HEAD. A PR whose head has no workflow file is allowed through as "no CI configured", logged; one whose head has a workflow file is refused. This departs from the issue's literal wording by the owner's choice.
3. Threat model (2026-11-16, after review round 5): the `done` gate defends against lazy or confused children, not against a child crafting Markdown or HTML to hide a PR. Children run as the owner's user with bypass permissions and could edit the gate itself, so a malicious child is out of scope. Findings that need deliberately crafted renderer-divergent input (review round 5's P3R5-1 to P3R5-7: odd HTML comments, entities, fences in list items, raw HTML tables) are recorded as out of scope, not fixed. A checkpoint an honest child writes by following templates/checkpoint.md and templates/brief.md must never slip the gate and must never be falsely refused. The spec and README state this threat model.
