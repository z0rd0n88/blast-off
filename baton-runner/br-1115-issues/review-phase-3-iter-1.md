## High Findings

### H1. Zero PRs read from Status cells: `done` passes with no CI read and no log line (introduced by this commit)

- **Location:** `lib/ci.sh:66-67` (the `for pr in $(sed ... | awk -F'|' '{ print $(NF-1) }' | ...)` list); reached from `lib/chain.sh:159`; `lib/receipt.sh:45-71` (also iterates plan rows only); `docs/spec.md:21-22,61,91` (table-less checkpoints documented as supported), `docs/spec.md:97` (silent on it); no case in `tests/41-ci-wait.sh`.
- **Description:** The PR list now comes only from the last cell of digit-keyed rows under a line starting `## Phase plan`. An empty list means zero loop iterations, then `chain_end 0 "job done"`. `run.log` cannot tell "CI read and green" from "no PR found, CI never read". For a table-less or unrecognised table, `receipt_check` and `receipt_all_done` are no-ops too, so the CI read was the only gate at `done` and it is gone. Measured on copies of the old and new `ci_check` with stubs:
  - code-reviewer: 5 samples flip from exit 10 to exit 0 in a git workdir with a workflow at HEAD and no CI record, 7 outside git.
  - security-reviewer: 10 of 10 samples that phase 2 refused ("PR #9 CI unread") now exit 0 with 0 log lines.
  - silent-failure-hunter: of 29 samples, 14 flip from refused to passed; 8 are parser-recognition cases.
  - penetration-tester: of 29 variants, 16 flip; 11 are parser-recognition failures.
  - tdd-guide: table-less, `## Phase Plan`, and done-row-without-PR samples all return 0 with no log line.
  - Shapes that flip: no table (PR in `Completed phases`), `## Phase Plan`, `### Phase plan`, `## Phases`, heading with a leading space, indented rows, rows with no leading pipe, row keys `P0`/`P1`/`A`/`**0**`, a tab before the key, a PR column before Status, a Notes column after Status whose cell starts `done`, `PR #N \| done (sha)`, and a done row whose Status holds no PR token while `Completed phases` names it (the shape `templates/checkpoint.md:47` prompts).
  - The commit replaced the old table-less `fin` fixture (prose `pr#07`, expecting exit 10) with a table, so the flip has no test in either direction (critical-thinking, penetration-tester).
  - Criterion 3 asks for Status-cell-only reading; it does not ask for the gate to vanish silently when no row parses. The child being gated writes the only cell the gate reads.
- **Suggested fix:** (1) Always log the set read at `done`: `CI read for PRs: 7 9`, or `no PR named in a Phase plan Status cell; CI not read`. (2) When `cp_phases` is 0, keep the old whole-file read (silent-failure-hunter, penetration-tester, security-reviewer), or refuse, or document that table-less jobs have no CI gate: the owner's call (code-reviewer, tdd-guide). (3) Log or refuse a done row whose Status cell names no PR. (4) Say in `docs/spec.md:97` that only digit-keyed rows are read and what a table-less checkpoint gets. (5) Add `41-ci-wait` cases: a table-less checkpoint with a prose `PR #N`, a done row with no PR token, one malformed row.
- **Attribution:** code-reviewer (HIGH, plus the table-less case as a separate MEDIUM with the same root cause), silent-failure-hunter (H1), security-reviewer (H1), penetration-tester (H1), tdd-guide (H1); (ct 1, ct 2).
